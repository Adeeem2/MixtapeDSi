# MixtapeDSi — Architecture

## Modules

```
SD (/music/) --libfat--> music_library (scan, bounded 512 tracks)
MP3 file --> Mp3Decoder (dr_mp3 streaming, 8 KiB file buf)
Mp3Decoder --> AudioStream (2x 2304-frame PCM bufs, pump/consumed)
AudioStream --> libnds PCM channel (ARM9 fill, DMA consume)
AudioStream clock --> PlaybackController (samples_played / rate = ms)
Playback clock --> lyric_timeline (binary search active line)
UI views read controller + timeline; never block pump.
```

## Audio pipeline detail

- `mp3_open`: skips ID3v2 (`metadata_audio_offset`), inits Helix decoder.
- Main loop calls `audio_stream_pump()` once per VBlank (legacy host path) /
  `audio_hw_pump()` on NDS: decodes **bounded frames** (Helix integer path,
  ~10x cheaper than float) into a ~420 ms ring; resamples >32768 Hz files to
  maxmod's 32768 Hz ceiling with an exact phase-carry linear interpolator.
- HW consume callback calls `audio_stream_consumed(frames)`; position = `(decoded - pending) / rate`.
- Track change: `audio_stream_close/open` (flushes stale PCM — no bleed), `pb_play_index` resets clock, LRC reloaded.
- Seek: `mp3_seek_ms` (dr_mp3 frame seek) + `pb_seek_ms`; pending buffers flushed.
- Underrun accounting: `underruns` counter incremented on decode error/starve; displayed in Settings (debug).

## Lyric sync

- `lrc_parse` builds sorted `LyricLine[timestamp_ms, text]` (max 256, truncation flagged).
- Per frame: `pos = audio_stream_position_ms()` (or `pb_position_ms` fallback) -> `lyric_active_index` (binary search) -> redraw line text only if index changed (`lyric_index_changed`).
- Karaoke sweep: `lyric_sweep_chars()` interpolates the sung prefix across `lyric_line_duration_ms()` (next timestamp, clamped 800..12000 ms; last line uses the track length). It is recomputed per frame and the 16px line is redrawn only when the glyph count advances.
- Pause: clock frozen (no pump, no advance). Seek: index recomputed from new clock (handles forward/backward jumps). Track end: song replaced, index resets.

## Memory budget (DS mode, 4 MB)

- ARM9 binary + libnds: ~1 MB; dr_mp3 working: ~200 KB; inbuf 8 KB; PCM 2x2304x2chx2B = ~18 KB; LRC 256x256 B = 64 KB; library 512 tracks x ~900 B = ~460 KB (largest; acceptable, else reduce LIB_MAX_TRACKS). Total < 2 MB.

## UI

- Views: Home / Now Playing / Library / Queue / Settings. Lyrics screen is
  fixed to TOP. Reduced-animation mode keeps the karaoke sweep but skips
  lyric glide and the ambient palette pulse.
- 256x192 layout with generated 8bpp surfaces and direct bounded tile-map
  text composition; libnds console initialization is retained only to
  provision the custom font tiles, not as the finished UI renderer.
- Both engines run `MODE_0_2D`. Layers (top screen): BG2 4bpp console text
  (`tile base 0`, `map 31`), BG1 4bpp 16px lyric text (`tile base 4`,
  `map 26`), BG3 8bpp static art (`tile base 1`, `map 28`). The bottom
  screen uses BG0 for console text and the same BG1/BG3 layout. BG1 at
  64 KB can never collide with the art tiles or the runtime EQ tiles
  appended after the generated ones.
- The lyric face is "Mixtape Sans", generated by `tools/make_lyric_font.py`
  from OFL Barlow Semi Condensed SemiBold into 8x16 4bpp glyphs (169
  glyphs, two stacked tiles). LRC lines wrap to 3 rows x 30 columns.
- The bottom deck is persistent art (glass card, vinyl, two-row seek rail,
  transport wells, segmented tabs). List views swap the card interior for
  a generated flat panel (`ui_panel`) and restore the vinyl art on return.
- One touch dispatcher runs outside the view branches: tabs, heart,
  transport, list rows, and timeline scrubbing work on every view.
  Scrub previews while the pen is held and commits `audio_hw_seek_ms()` on
  release; the HW clock keeps a seek baseline so `audio_hw_position_ms()`
  remains monotonic across seeks.
